# Linux ディレクトリ構造

このドキュメントでは、Linux の基本的なディレクトリ構造について説明します。

## Linux のファイルシステム階層

Linux では、すべてのファイルとディレクトリが `/`（ルート）から始まる単一のツリー構造で管理されています。各ディレクトリには特定の役割があり、システムの動作を理解する上で重要です。

## ディレクトリ構造の全体像

```
/
├── bin/          基本コマンド
├── sbin/         システム管理コマンド
├── etc/          設定ファイル
├── home/         ユーザーホームディレクトリ
├── root/         root ユーザーのホーム
├── var/          変動データ（ログ、キャッシュ等）
├── tmp/          一時ファイル
├── usr/          ユーザープログラム
│   ├── bin/
│   ├── sbin/
│   ├── lib/
│   ├── local/
│   └── share/
├── opt/          オプションパッケージ
├── lib/          システムライブラリ
├── dev/          デバイスファイル
├── proc/         プロセス情報（仮想）
├── sys/          システム情報（仮想）
├── boot/         起動ファイル
├── mnt/          マウントポイント（手動）
└── media/        マウントポイント（自動）
```

---

## 主要なディレクトリ

### /bin (Binaries)

システムの基本的なコマンド（バイナリファイル）が格納されているディレクトリです。

**用途:**

- すべてのユーザーが使用できる基本コマンド
- システムの起動やシングルユーザーモードで必要なコマンド
- システムが正常に動作するために必要な最小限のコマンド

**代表的なファイル:**

- `ls` - ファイル一覧表示
- `cp` - ファイルコピー
- `mv` - ファイル移動
- `cat` - ファイル内容表示
- `bash` - シェル
- `grep` - テキスト検索

---

### /sbin (System Binaries)

システム管理用のコマンドが格納されているディレクトリです。

**用途:**

- システム管理者（root）が使用するコマンド
- システムのメンテナンスや設定に必要なコマンド
- ブート時やシステム復旧時に使用するコマンド

**代表的なファイル:**

- `ifconfig` - ネットワーク設定
- `reboot` - システム再起動
- `shutdown` - システムシャットダウン
- `fdisk` - ディスクパーティション管理
- `iptables` - ファイアウォール設定

---

### /etc (Et Cetera / Editable Text Configuration)

システム全体の設定ファイルが格納されているディレクトリです。

**用途:**

- システム設定ファイル
- アプリケーション設定ファイル
- スタートアップスクリプト
- ユーザー管理情報

**代表的なファイル・サブディレクトリ:**

- `passwd` - ユーザーアカウント情報
- `group` - グループ情報
- `hosts` - ホスト名とIPアドレスのマッピング
- `fstab` - ファイルシステムのマウント情報
- `ssh/` - SSH設定
- `nginx/` または `apache2/` - Webサーバー設定
- `systemd/` - systemd関連の設定

**注意:** このディレクトリのファイルを変更する際は、バックアップを取ることを推奨します。

---

### /home

一般ユーザーのホームディレクトリが格納されているディレクトリです。

**用途:**

- 各ユーザーの個人ファイル
- ユーザー固有の設定ファイル
- ドキュメント、ダウンロード、デスクトップなど

**例:**

- `/home/username/` - ユーザー "username" のホームディレクトリ
- `/home/username/.bashrc` - ユーザー固有のbash設定
- `/home/username/.ssh/` - ユーザーのSSH鍵

**特徴:**

- 各ユーザーは自分のホームディレクトリに対してフルアクセス権を持つ
- 他のユーザーのホームディレクトリは通常、読み取り専用または非アクセス

---

### /root

root ユーザー（管理者）のホームディレクトリです。

**用途:**

- システム管理者専用のファイル
- 管理用スクリプトや設定

**特徴:**

- `/home` 配下ではなく、ルート直下に配置されている
- システムの重要なメンテナンスに備えて、ルートパーティションに配置

---

### /var (Variable)

変動するデータを格納するディレクトリです。

**用途:**

- ログファイル
- データベース
- メールキュー
- 一時的なプロセスデータ
- キャッシュファイル

**代表的なサブディレクトリ:**

- `/var/log/` - システムとアプリケーションのログ
  - `syslog` - システムログ
  - `auth.log` - 認証ログ
  - `nginx/` または `apache2/` - Webサーバーログ
- `/var/www/` - Webサーバーのドキュメントルート
- `/var/lib/` - プログラムの状態データ、データベース
- `/var/cache/` - アプリケーションのキャッシュデータ
- `/var/tmp/` - 再起動後も保持される一時ファイル

**特徴:**

- 頻繁に書き込みが発生するため、別パーティションに分けることも多い
- ディスク容量の監視が重要

---

### /tmp (Temporary)

一時ファイルを格納するディレクトリです。

**用途:**

- アプリケーションの一時ファイル
- プロセス間通信用のソケットファイル
- 短期的なデータ保存

**特徴:**

- すべてのユーザーが読み書き可能
- システム再起動時にクリアされることが多い
- 定期的に古いファイルが削除される場合がある

**注意:** 重要なデータを `/tmp` に置くべきではありません。

---

### /usr (Unix System Resources)

ユーザープログラムとデータを格納するディレクトリです。

**用途:**

- ユーザーアプリケーション
- ライブラリ
- ドキュメント
- ソースコード

**代表的なサブディレクトリ:**

- `/usr/bin/` - ユーザーコマンド（システム必須ではない）
  - `python`, `gcc`, `git` など
- `/usr/sbin/` - システム管理コマンド（必須ではない）
- `/usr/lib/` - 共有ライブラリ
- `/usr/local/` - ローカルにインストールしたソフトウェア
  - `/usr/local/bin/` - 手動でインストールしたコマンド
  - `/usr/local/lib/` - 手動でインストールしたライブラリ
- `/usr/share/` - アーキテクチャ非依存のデータ
  - ドキュメント、マニュアルページ、設定ファイルのサンプル
- `/usr/src/` - ソースコード

**特徴:**

- 読み取り専用でマウントされることが多い
- システムの基本機能には影響しない

---

### /opt (Optional)

オプションのアプリケーションパッケージを格納するディレクトリです。

**用途:**

- サードパーティ製ソフトウェア
- 独立したアプリケーションパッケージ
- ベンダー提供のソフトウェア

**例:**

- `/opt/google/chrome/` - Google Chrome
- `/opt/teamviewer/` - TeamViewer
- `/opt/myapp/` - カスタムアプリケーション

**特徴:**

- アプリケーションごとに専用のディレクトリを持つ
- システムの他の部分から独立している

---

### /lib (Libraries)

システムの基本的なライブラリファイルを格納するディレクトリです。

**用途:**

- `/bin` と `/sbin` のコマンドが使用する共有ライブラリ
- カーネルモジュール
- システム起動に必要なライブラリ

**関連ディレクトリ:**

- `/lib64/` - 64ビットシステム用のライブラリ（64ビットシステムの場合）
- `/lib/modules/` - カーネルモジュール

**特徴:**

- システムの基本動作に必要
- アプリケーション用のライブラリは `/usr/lib/` に配置

---

### /dev (Devices)

デバイスファイルを格納するディレクトリです。

**用途:**

- ハードウェアデバイスへのインターフェース
- 仮想デバイス
- デバイスドライバとの通信

**代表的なファイル:**

- `/dev/sda` - 1番目のハードディスク
- `/dev/sda1` - 1番目のハードディスクの1番目のパーティション
- `/dev/null` - データを破棄する特殊デバイス
- `/dev/zero` - ゼロバイトを無限に生成する特殊デバイス
- `/dev/random` - ランダムデータを生成
- `/dev/tty` - ターミナルデバイス

**特徴:**

- 動的に生成される（udev等によって）
- ファイルとして見えるが、実際はデバイスへのインターフェース

---

### /proc (Process)

プロセスとシステム情報を提供する仮想ファイルシステムです。

**用途:**

- 実行中のプロセス情報
- システムのリソース情報
- カーネル設定の参照・変更

**代表的なファイル・ディレクトリ:**

- `/proc/cpuinfo` - CPU情報
- `/proc/meminfo` - メモリ使用状況
- `/proc/[PID]/` - プロセスID [PID] の情報
  - `/proc/[PID]/status` - プロセスのステータス
  - `/proc/[PID]/cmdline` - プロセスの起動コマンド
- `/proc/sys/` - カーネルパラメータ（読み書き可能）

**特徴:**

- 実際のファイルではなく、カーネルが動的に生成
- ディスク容量を消費しない
- システム情報の取得に便利

**使用例:**

```bash
# CPU情報を確認
$ cat /proc/cpuinfo

# メモリ使用状況を確認
$ cat /proc/meminfo

# 特定プロセスの情報を確認
$ cat /proc/1234/status
```

---

### /sys (System)

デバイスとカーネルの情報を提供する仮想ファイルシステムです。

**用途:**

- デバイス情報
- カーネルサブシステムの情報
- ハードウェアの設定変更

**代表的なサブディレクトリ:**

- `/sys/block/` - ブロックデバイス情報
- `/sys/class/` - デバイスクラス（ネットワーク、USB等）
- `/sys/devices/` - デバイスツリー

**特徴:**

- `/proc` と同様に仮想ファイルシステム
- より構造化されたハードウェア情報を提供
- systemd や udev が参照する

---

### /boot

システム起動に必要なファイルを格納するディレクトリです。

**用途:**

- カーネルイメージ
- ブートローダー設定
- 初期RAMディスク

**代表的なファイル:**

- `vmlinuz` - Linux カーネル
- `initrd.img` または `initramfs` - 初期RAMディスク
- `grub/` - GRUBブートローダーの設定
- `config-*` - カーネル設定ファイル

**特徴:**

- システムの起動に不可欠
- 誤った変更はシステムを起動不能にする可能性がある
- 通常、別パーティションに配置されることが多い

---

### /mnt と /media

外部デバイスのマウントポイントとして使用されるディレクトリです。

#### /mnt (Mount)

**用途:**

- 一時的なファイルシステムのマウント
- 手動でマウントする際の慣習的な場所
- ネットワークドライブのマウント

**例:**

```bash
# USBドライブを手動でマウント
$ sudo mount /dev/sdb1 /mnt

# ネットワークドライブをマウント
$ sudo mount -t nfs server:/share /mnt/network
```

#### /media

**用途:**

- リムーバブルメディアの自動マウント
- USB、CD/DVD、外付けHDDなど

**例:**

- `/media/username/USB_DRIVE/` - 自動マウントされたUSBドライブ

**特徴:**

- `/mnt` は手動マウント用
- `/media` は自動マウント用
- 最近のディストリビューションでは `/media` が主に使用される

---

### 注意点

1. **システムディレクトリを変更する際は慎重に**
   - `/etc`, `/boot`, `/bin`, `/sbin` などの変更は、システムに影響を与える可能性があります
   - 変更前には必ずバックアップを取りましょう

2. **権限を理解する**
   - 多くのシステムディレクトリは root 権限が必要です
   - `sudo` を使用する際は、実行内容を理解してから実行しましょう

3. **ログとディスク容量**
   - `/var/log` は定期的に確認してディスク容量を監視しましょう
   - 不要なログファイルは適切にローテーションまたは削除しましょう

---

## ディレクトリを探索する際のヒント

### よく使うコマンド

```bash
# ディレクトリの内容を確認
$ ls -la /etc

# ディレクトリのサイズを確認
$ du -sh /var/log

# ディレクトリツリーを表示（treeコマンドが必要）
$ tree -L 2 /usr

# ディスク使用状況を確認
$ df -h
```
---

## まとめ

Linux のディレクトリ構造は、それぞれが明確な役割を持っています：

- **システムの基本**: `/bin`, `/sbin`, `/lib`, `/boot`
- **設定**: `/etc`
- **ユーザーデータ**: `/home`, `/root`
- **変動データ**: `/var`, `/tmp`
- **アプリケーション**: `/usr`, `/opt`
- **仮想システム**: `/dev`, `/proc`, `/sys`
- **マウントポイント**: `/mnt`, `/media`

この構造を理解することで、ファイルの配置場所が予測しやすくなり、トラブルシューティングやシステム管理が効率的になります。
